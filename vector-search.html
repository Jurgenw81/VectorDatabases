Vector databases explained

What is actually happening when you search?

A vector search system does not ask whether a filename contains your words. It converts content into numerical coordinates called embeddings, then searches for nearby coordinates. That is why a query like “dog playing in snow” can retrieve an image named IMG_4832.jpg.

01

Turn content into embeddings

An embedding model converts an image, sentence or document chunk into a vector: a long array of floating-point numbers. Those numbers encode learned features of the content.

→
0.021-0.1840.7340.091-0.441…

The values above illustrate the shape of an embedding; they are not the actual CLIP vector for this photo. CLIP ViT-B/32 produces a high-dimensional representation.

02

Meaning becomes geometry

The useful information is the relationship between vectors. Semantically related items tend to occupy nearby regions of the learned embedding space. A two-dimensional picture makes the idea visible, although the real space has many more dimensions.

03

Store vectors and keep a mapping back to files

FAISS stores the vectors in an index. Your metadata JSON keeps the corresponding file paths. The FAISS position/ID is therefore the bridge from a numerical nearest-neighbor result back to the file on disk.

FAISS VECTOR INDEXimages.faiss + images.json
#0dog-snow-01.jpg[0.021, -0.184, 0.734, …]
#1red-sports-car.jpg[-0.284, 0.651, 0.092, …]
#2mountain-sunset.jpg[0.481, 0.103, -0.291, …]

FAISS is best described here as a vector similarity-search library/index, not a full general-purpose database server.

04

Your text query becomes a vector too

CLIP was trained so images and text can be represented in a compatible embedding space. The text “dog playing in snow” is encoded, normalized, and compared with the normalized image embeddings.

05

Nearest-neighbor search finds the closest meanings

Which stored image vectors are most similar to the query vector?

This project L2-normalizes the vectors and uses faiss.IndexFlatIP. For unit-length vectors, the inner product equals cosine similarity, so sorting by inner product gives the same ranking as sorting by cosine similarity.

Cosine similaritysimilarity(A, B) = (A · B) / (‖A‖ ‖B‖)

after normalization: ‖A‖ = ‖B‖ = 1  →  similarity(A, B) = A · B

What the project supports

One idea, three useful search modes.

T→I

Text → Image

Embed a natural-language query with CLIP and retrieve nearby image embeddings.

I→I

Image → Image

Embed a reference image and retrieve the nearest images from the same CLIP space.

T→T

Text → Text

Chunk documents, embed chunks with MiniLM, then retrieve semantically related passages.

IP

Cosine-style ranking

L2-normalized vectors plus inner product provide cosine-similarity ordering.

The Python behind it

The browser explains it. Python actually does it.

When you run the CLI, the embedding model produces the real vectors and FAISS performs the real similarity search.

local_search.pytext → image search
# 1. Encode the text in CLIP's shared image/text space
query_vector = image_model.encode([query]).astype("float32")

# 2. Unit-normalize the query
faiss.normalize_L2(query_vector)

# 3. Search the stored image vectors
scores, ids = image_index.search(query_vector, limit)

# 4. Use returned IDs to look up the original file paths
for score, idx in zip(scores[0], ids[0]):
    print(image_metadata[idx]["path"], score)

Models and responsibilities
FAISS does not understand dogs. The embedding model does.
This distinction matters: the model creates a useful semantic geometry; FAISS efficiently searches the numerical vectors placed in that geometry.
sentence-transformers/clip-ViT-B-32
Creates compatible embeddings for images and text, enabling text-to-image and image-to-image retrieval.
sentence-transformers/all-MiniLM-L6-v2
Creates semantic vectors for text chunks and text queries, enabling meaning-based document retrieval.

Local first
Your searchable library stays on your machine.
The models need to be downloaded initially. After that, the project can create embeddings, store FAISS indexes and search your local collection without sending your personal image/document library to a hosted vector database.


The core idea
Semantic search is geometry.
Encode meaning as vectors, normalize them, store them, turn the query into another vector, and retrieve the nearest neighbors. The UI is the visible part; that vector pipeline is the project.
